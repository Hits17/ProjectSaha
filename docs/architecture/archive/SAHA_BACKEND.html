1 · What the backend is

The Saha backend is a single FastAPI application (apps/backend) running on uvicorn, fully asynchronous end-to-end: SQLAlchemy 2.0 async ORM over asyncpg to PostgreSQL, async HTTP to every external service. It is the system of record and the policy engine for the entire IP deal funnel — identity, listings, discovery, negotiation, legal, settlement, reviews, demand, administration, and the social layer.

api/ — routers (HTTP boundary) services/ — business logic db/models/ — ORM tables ai/ — provider-agnostic LLM integrations/ — outbound adapters core/ — cross-cutting plumbing

One rule per layer

Routers validate, authorize, and translate HTTP ⇄ Python — never touch crypto or external SDKs directly. Services hold all business logic and own the DB session. Integrations wrap one external system each.

Async or nothing

Every handler, service function, and integration call is async. The DB session is request-scoped (Depends(get_db)); AI/Stripe/MinIO/Qdrant calls are awaited HTTP. Nothing blocks the event loop.

Security by construction

A 3-rung dependency ladder (get_current_user → require_verified_user → require_admin) gates handlers; vault bytes are AES-256-GCM; refresh tokens rotate with theft detection; production boot is guarded.
How to read this document. It is organised by component, not by feature. Start at the layered anatomy for the request path, then the vertical slice shows the one pattern every feature repeats. The router/service/model catalogues then enumerate every moving part. Diagrams render live via Mermaid (CDN — needs internet once).

  1. Middleware (outermost) attaches a request-id, times the request, rejects oversized bodies (size guard), sets the full security-header set (CSP · frame-deny · nosniff · Permissions-Policy · COOP · HSTS in prod), applies gzip + CORS, and SlowAPIMiddleware enforces rate limits on every route (default_limits) keyed per-user/IP, with stricter tiers on auth, money-movement, and AI/upload endpoints.
  2. Dependencies resolve before the handler body: a request-scoped DB session is opened, the bearer token is decoded into a User, and KYC/role guards run — returning 401/403 before any business code executes.
  3. Router validates the request body against a Pydantic schema, performs authorization specific to the resource (ownership, membership), calls the service, and maps the ORM object to a response schema.
  4. Service holds the business rules and owns the transaction (commit/refresh); it is the only layer that may call integrations or the AI client.
  5. Models are SQLAlchemy 2.0 mapped classes — the single source of truth for table shape; asyncpg executes the SQL.
  6. Side-channels: business metrics increment in the service; the audit log is written by a BackgroundTask in a fresh session so it never blocks or rolls back with the main transaction.

4 · Application factory & lifespan

app/main.py builds the FastAPI instance and is the single wiring point. Two things matter most: the lifespan context manager and the order of registration.

Lifespan — startup gates and resource priming

  1. Boot guard: validate_production_settings(settings) runs first. If APP_ENV=production and any insecure dev default remains, it raises and refuses to start (see §6).
  2. MinIO: storage.ensure_bucket_exists() creates the vault bucket if missing (warns, doesn't crash).
  3. Qdrant: vector.ensure_collection_exists() creates the ip_listings collection at 1024-dim cosine (warns, doesn't crash).
  4. On shutdown: await engine.dispose() drains the connection pool.
Eager metrics import. from app.core import metrics # noqa sits at module top of main.py on purpose: custom counters are otherwise only imported lazily inside services, so they wouldn't register in the default Prometheus registry until a service first ran. Eager import exposes them at 0 from startup. (See §20.)

5 · Middleware pipeline

Middleware is the outermost ring; it wraps every request including unauthenticated ones. The custom HTTP middleware does five jobs in one pass:

ResponsibilityDetail
Request-ID propagationReads X-Request-ID or generates a UUID; binds it (plus method + path) into structlog contextvars so every log line in the request is correlated; echoes it back on the response header.
Access logging + timingMeasures duration_ms with perf_counter; emits one structured request log with status + duration. Skips /health/live and /metrics/ to avoid noise.
Crash containmentWraps call_next in try/except; an unhandled error logs unhandled_error with traceback and returns a clean JSON 500 carrying the request-id (never a stack trace to the client).
Security headersX-Content-Type-Options: nosniff, X-Frame-Options: DENY, Referrer-Policy: strict-origin-when-cross-origin, and Strict-Transport-Security when in production.
Context cleanupClears structlog contextvars in a finally so request state never leaks between requests on the same worker.

Then framework middleware runs: TrustedHost (host allow-list, no-op in dev), GZip (responses ≥1 KB), and CORS (credentialed, explicit origins/methods/headers). The SlowAPI limiter is wired via app state and a dedicated 429 exception handler.

6 · Configuration & boot guards

app/core/config.py is a Pydantic Settings object loaded from apps/backend/.env. It groups every knob: app identity, database/Redis URLs, MinIO, Qdrant, SMTP, the AI provider trio, JWT params, CORS, Persona KYC, Stripe, DocuSign, the vault key, and the host allow-list.

is_production

True when APP_ENV == "production". Gates HSTS emission, the boot guard, and Swagger/redoc exposure (docs_url only when DEBUG).

validate_production_settings()

Returns a list of fatal misconfigurations; a non-empty list aborts startup. It is the difference between "misconfigured" and "insecurely live".

The production boot guard checks

  • Any field still equal to a known insecure dev default (e.g. the dev SECRET_KEY/VAULT_ENCRYPTION_KEY) → blocked.
  • DEBUG must be false.
  • KYC_MOCK_MODE must be false (no fake identity verification in prod).
  • ALLOWED_HOSTS must list explicit hostnames (no *).
  • CORS_ORIGINS must not contain any http://localhost origin.
Fail closed. The guard runs inside the lifespan startup, so a misconfigured production deploy never serves a single request — it crashes the worker with a precise list of problems in the logs.

7 · Database layer

app/db/session.py is small but load-bearing.

engine = create_async_engine(DATABASE_URL, echo=DEBUG,
                             pool_pre_ping=True, pool_size=10, max_overflow=20)
AsyncSessionLocal = async_sessionmaker(engine, class_=AsyncSession,
                                       expire_on_commit=False,   # ← important
                                       autocommit=False, autoflush=False)
class Base(DeclarativeBase): pass
async def get_db():  # request-scoped session; rollback on error, always close
    async with AsyncSessionLocal() as session:
        try: yield session
        except Exception: await session.rollback(); raise
        finally: await session.close()
  • pool_pre_ping validates pooled connections before use — survives Postgres restarts/idle drops on the edge device.
  • expire_on_commit=False keeps attributes readable after commit(). The trade-off: a re-fetch in the same session returns the identity-map copy, so relationships aren't auto-refreshed — services that need fresh relations add .execution_options(populate_existing=True) (see §23).
  • get_db is the dependency every router injects; one session per request, rolled back on any exception.

Beyond the ladder, routers/services add resource-level guards: ownership (require_seller, require_owner, "not your listing"), participation (proposal buyer/seller), and membership (community chat). 10 · Auth service & token rotation

app/services/auth.py implements registration, login, refresh, and logout. Two details are security-critical.

Login is timing-equalized

A module-level _DUMMY_HASH is verified when the email doesn't exist, so a login against an unknown account takes the same ~bcrypt time as a wrong password against a real one — defeating timing-based user enumeration.

Refresh tokens rotate as families with theft detection

Refresh-token family rotation & reuse detection
sequenceDiagram
  autonumber
  participant C as Client
  participant A as auth service
  participant DB as refresh_tokens
  C->>A: POST /refresh (raw token)
  A->>DB: find by sha256(raw), not expired
  alt token already used (used_at set)
    A->>DB: DELETE every token in family_id
    A-->>C: 401 "Token reuse detected"
  else fresh token
    A->>DB: mark used_at = now
    A->>DB: INSERT new token (same family_id)
    A-->>C: new access + new refresh
  end

Each login starts a new family_id. Every refresh marks the presented token used and issues a successor in the same family. If a used token is ever presented again (a sign it was stolen and replayed), the entire family is invalidated and the user must log in again. Access tokens are stateless JWTs; refresh tokens are the only server-side session state, stored as hashes.

11 · The vertical slice — one pattern, repeated

Every feature in Saha is the same five files. Learn it once and the whole codebase is legible. Using materials/communities as the template:

The contract between router and service. The router decides who may call (guards, ownership) and what the wire shape is (schemas). The service decides what actually happens. Errors that the client should see are raised as HTTPException from whichever layer first detects them.

19 · Audit logging

app/core/audit.py exposes one function, write_audit_log(...), designed to be scheduled via FastAPI BackgroundTasks. It opens its own fresh session so the audit write never blocks, rolls back with, or accidentally commits the request's main transaction. Every security-relevant mutation (create, update, archive, join, dispute, KYC override, disbursement…) schedules one. The metadata dict is stored in the JSONB column mapped as log_metadata (the attribute name avoids SQLAlchemy's reserved metadata).

20 · Metrics

app/core/metrics.py defines the saha_* business counters/histograms once at import time. They're mounted at /metrics/ (trailing slash — bare /metrics 307-redirects) via the Prometheus ASGI app. Counters span the funnel: searches, listings published, materials created, communities created & community messages, proposals/transactions/reviews, plus money histograms (deal value, disbursed, commission). Services call .inc()/.observe() on success.

21 · Rate limiting

app/core/ratelimit.py is a SlowAPI Limiter keyed by a custom function: if a valid Bearer token is present it keys per user:{sub}; otherwise it honours X-Forwarded-For (set by the reverse proxy) and falls back to the client IP. Storage is Redis with an in-memory fallback so the API keeps serving (per-process limits) if Redis is down. Routers apply @limiter.limit(...) to sensitive endpoints (login/register 10/min, refresh 60/min, search 30/min).

22 · Structured logging

app/core/logging.py configures structlog: pretty colourised console in dev, JSON lines in production. The request middleware binds request_id, method, and path into contextvars, so every log emitted during a request is automatically correlated, and each request closes with one request line carrying status + duration_ms.

23 · Conventions & gotchas

The hard-won rules that keep the async ORM and the ARM64 edge host happy. Violating one of these is how most bugs here start.

RuleWhy
bcrypt directly, never passlibpasslib is incompatible with bcrypt≥4 on ARM64 (crash on import).
Enums: create_type=False + values_callableTypes are pre-created in SQL; without the callable SQLAlchemy sends the enum name, not its value.
populate_existing=True when re-fetching after commitexpire_on_commit=False returns the cached identity-map object; relationships won't refresh otherwise. Never db.expire() before a re-fetch (triggers a sync lazy-load → MissingGreenlet).
Re-fetch with selectinload before returningAfter create, relationships aren't loaded; serializing them lazily raises MissingGreenlet 500. Load every relation the response schema declares.
BYTEA needs explicit LargeBinaryMapped[bytes] alone may not map to BYTEA reliably.
No ::TYPE casts in text() with named bindsSQLAlchemy treats :: as an escaped colon → the bind is never substituted. Use CAST(:x AS JSONB).
qdrant-client 1.18: query_points, not searchsearch() was removed; results are response.points (each has .score + .payload).
Eager-import metrics in main.pyOtherwise counters register only when a service first runs, and /metrics/ shows nothing until then.
Scrape /metrics/ with the trailing slashBare /metrics 307-redirects; Prometheus must use metrics_path: /metrics/.
