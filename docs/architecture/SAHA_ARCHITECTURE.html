Standalone project collaboration

Create an invite-only project directly from Projects with a name and goal. A library resource is optional. The November migration makes older projects private while preserving their membership and restricts associated posts to the community audience.

Owners/moderators add existing Saha users by email through Members & invitations. This currently grants membership immediately; it is not a pending invitation acceptance workflow. Members can leave, and managers can remove members. Existing Matrix grants must be revoked before removal is confirmed.

References store an HTTPS URL, title, notes, selected platform and file type. Members browse/filter/copy links; authors or managers edit/remove them. Only managers pin. A version check rejects stale edits with 409 and a project has at most 200 references. Bundled SVG badges avoid fetching third-party favicons. The destination hostname remains visible; the selected icon is not identity verification.

The server never retrieves, indexes or copies linked files. Original platform permissions still apply. References and tasks are access-controlled database records, not encrypted chat. Existing task assignment, three-column status board, project stages and contribution guides are retained.

Social interaction and media

One composer/card system serves the member feed and public institution updates. Compose text, optional titles and links, up to six media attachments (at most one video), keyboard-selectable member mentions and topic hashtags. Feed views include latest/ranked, followed authors, saved posts and server-side text search.

JPEG/PNG/WebP images are limited to 8 MiB; MP4/WebM video to 40 MiB. The API bounds reads, checks MIME signatures and stores opaque object keys. Draft uploads are owner-only with per-owner draft quotas; attaching is atomic and single-use. Downloads enforce the current post policy before storage access and use private/no-store. Image/video decoding, malware scanning, transcoding and streaming/range delivery are not implemented.

Six expressive reactions are independent from reputation votes. Editing clears endorsements; report/moderation behavior is preserved. Replies are one level deep, existing vote ranking is retained, and orphan replies remain visible without revealing deleted parent text. Sharing with thoughts creates a link post, not a native repost record or counter.

Mention labels are normalized to active account identities. Notification recipients must be able to see the post; notifications do not copy private post text. Admin moderation can inspect attachments with authenticated blob fetches. Text classifiers do not claim to classify visual media.

Encrypted chat

Projects reuse the community encrypted-room scope. Saha proves ownership of a personal Matrix identity using a temporary access token plus password/MFA step-up, stores only the Matrix identity, and coordinates room policy/invites/removal.

Element performs encryption and decryption on member devices. The dedicated membership bot must have no device encryption keys. Rooms require encryption, private invitation, joined-only history and non-federation. Ordinary users cannot change room state or send unencrypted message events.

Legacy community/proposal chat returns HTTP 410; historical records are not migrated or relabeled as E2EE. If the provider is unavailable or not configured, the interface reports that state and does not fall back to plaintext. Real device verification, ciphertext inspection, key rotation after removal and recovery tests remain required.

Preserved IP tools

IP listings, BOM, discovery, protected vault assets, proposals, legal/contract state, settlement, disputes, reviews, demand and admin ledger remain in the repository. They are optional workflows. Collaboration does not require a payment or transaction.

Existing financial KYC, step-up, admin MFA, party/state authorization, production configuration guards and append-only audit controls remain relevant. Do not use the archived architecture as proof a planned payment, legal, Azure or compliance integration has shipped. The dated security audit retains the original risks and remediation evidence.

Release and operations

Use saha stop → migration/backup helper → saha build → saha start --local → saha versions --local → saha online → saha versions. The social/workspace helper performs the backup, stops apps, applies only the two November migrations, builds and starts locally; it leaves the tunnel stopped.

Never replace a running .next tree. Build receipts, required route manifests and X-Saha-Build identify source. A read-only schema gate refuses startup when required model columns are missing. nginx serves frontend/API on the public origin and admin only through the private listener.

No dependencies were added for this release. Use frozen pnpm and uv lockfiles, the isolated test stack and explicit migration dependency order. The original host checkout retains a nested frontend repository. The prepared ProjectSaha publication checkout includes frontend source as ordinary files for a complete clone; see docs/REPOSITORY-PUBLISHING.md for upload status.
